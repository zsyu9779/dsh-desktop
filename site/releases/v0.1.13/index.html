DeepSeek Harness Desktop v0.1.13

Restores the right sidebar's document preview on every WebView by supplying the one global older WebKit lacks, instead of switching the module off.

What changed

  • Re-enabled the upstream ui-sidebar-documentpreview client module, which v0.1.12 disabled because one line in its bundle feature-detects the Iterator global at module scope and throws wherever WebKit lacks it (Safari before 18.4, that is macOS before 15.4).
  • Added dsh-webview-compat, a host-side plugin that contributes a small <head> script defining Iterator only when it is missing, ahead of the client module graph. On a WebView that already has the global the script does nothing.
  • The shim resolves the real %IteratorPrototype% instead of creating a placeholder object, so the fallback method the bundled parser installs reaches every iterator rather than an object nothing inherits from.
  • Upgrading removes the disable row v0.1.12 wrote into the DSH profile, so the document tab returns without editing any local file by hand.
  • Everything else is unchanged from v0.1.12: the pinned upstream runtime @deepseek-ai/dsh@0.1.5-rc.1, the Node.js floor of 24.2 on the 24.x line, the other four preinstalled plugins, trusted-LAN phone remote, account login and desktop notifications.

Known limitations

  • Phone access is for a trusted LAN, not a public internet relay. The host uses HTTPS and device pairing; do not expose it directly to the internet.
  • Node.js and npm must be installed separately.
  • Windows executables are not code-signed; macOS packages are signed with a Developer ID certificate and notarized.
  • Upstream DeepSeek Harness remains in developer preview and may introduce compatibility-breaking changes.
