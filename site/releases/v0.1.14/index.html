DeepSeek Harness Desktop v0.1.14

External session links now open in the system browser, the legacy agent-preset shim is retired, and the pinned upstream runtime moves to the latest 0.1.5 release candidate.

What changed

  • Added dsh-webview-links, a host-side plugin that forwards a session's target="_blank" http(s) link clicks to the desktop shell, which opens them in the system browser. Wails v2's macOS WebView declares a WKUIDelegate without a new-window callback, so those clicks were previously swallowed with no navigation and no error.
  • The shell validates the message source and origin before forwarding, and the Go binding accepts only http:/https: URLs that carry a host, so file:, javascript: and custom app schemes never reach the OS opener.
  • Retired the agent-preset-compat plugin. DSH 0.1.7 replaced directory agent presets with plugin composition bundles and renamed @deepseek-ai/dsh-agent-presets to the singular @deepseek-ai/dsh-agent-preset, so the old code→ptc alias no longer applies. Upgrading removes the plugin from the DSH profile and deletes the row it wrote into cordis.patch.yml.
  • Pinned the upstream runtime to @deepseek-ai/dsh@0.1.5-rc.3, a dependency-pinning maintenance release on the 0.1.5 line with no session-format, CLI, host or plugin-API changes.
  • Everything else is unchanged from v0.1.13: dsh-webview-compat (the Iterator shim for older WebKit), open-editor, diff-review, account-login, trusted-LAN phone remote, account login and desktop notifications.

Known limitations

  • Phone access is for a trusted LAN, not a public internet relay. The host uses HTTPS and device pairing; do not expose it directly to the internet.
  • Node.js and npm must be installed separately.
  • Windows executables are not code-signed; macOS packages are signed with a Developer ID certificate and notarized.
  • Upstream DeepSeek Harness remains in developer preview and may introduce compatibility-breaking changes. The next upstream line (0.1.7) changes plugin slots, agent presets and settings storage, so it needs a dedicated adaptation release rather than a pin bump.
