DeepSeek Harness Desktop v0.1.15

Adapts to DeepSeek Harness 0.1.7-rc.1, whose multi-instance Session model changed the client plugin APIs, and re-scopes diff review to the git working tree.

What changed

  • Pinned the upstream runtime to @deepseek-ai/dsh@0.1.7-rc.1. In 0.1.7 the client Session model became multi-instance: slot components now derive state from useConversation/useProjection instead of a session nodes snapshot, tool-result diff views moved to the Host's workspace/changes endpoints, and the per-plugin settings slot (settings.plugin.item) was replaced by settings.plugins.tab.
  • Rebuilt diff-review from source against 0.1.7 and re-scoped it to its git working-tree review: staged/unstaged/untracked changes, per-file accept/revert, commit, push and AI review. The session-change review is now provided natively by upstream's changed-files card, so that tab was removed; the page-level “add selected text to conversation” affordance was also removed, because 0.1.7 no longer exposes a current-session id to root-scoped panels.
  • The preinstalled plugins' existing peer ranges still satisfy 0.1.7's compatibility preflight (it matches prerelease versions), so no plugin is rejected at startup.
  • open-editor, account-login, webview-compat and webview-links continue unchanged. webview-compat still supplies the Iterator global older WebKit lacks, and webview-links still routes external session links to the system browser.
  • agent-preset-compat remains retired, and the file-changes and subagent-max plugins an earlier release installed are still removed on upgrade.

Verification

Adapted plugins pass tsc --noEmit and their production bundle build; the desktop shell builds and its Go test suite passes; and an isolated end-to-end run of @deepseek-ai/dsh@0.1.7-rc.1 with the shipped preinstall set loads the Web UI with no plugin console errors.

Known limitations

  • diff-review no longer reviews in-conversation session changes; use the upstream changed-files card for those. Its git working-tree review is unchanged in intent.
  • Phone access is for a trusted LAN, not a public internet relay. The host uses HTTPS and device pairing; do not expose it directly to the internet.
  • Node.js and npm must be installed separately.
  • Windows executables are not code-signed; macOS packages are signed with a Developer ID certificate and notarized.
  • Upstream DeepSeek Harness remains in developer preview and may introduce compatibility-breaking changes.
