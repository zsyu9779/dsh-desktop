DeepSeek Harness Desktop v0.1.17

Restores external session links in the desktop shell after the move to DeepSeek Harness 0.2.x, which opens them through a window.open call the macOS WebView cannot answer.

What changed

  • Fixed external links in a session no longer opening the system browser. DSH 0.2 answers a Markdown link from its own onClick: it calls preventDefault() and then window.open(url, "_blank") for the "browser" link-opening mode. Wails' WKWebView declares a WKUIDelegate without a new-window callback, so that call was dropped with no navigation and no error, and webview-links previously listened in the bubble phase and yielded to a click the app had already claimed.
  • The injected head script now overrides window.open and forwards http(s) URLs to the shell, which opens them through the same OpenExternalURL path as the app's own “open in browser” button. The bubble-phase target="_blank" fallback remains for clients that render links without their own handler, and only claims clicks no in-app handler has claimed. The "sidebar" link-opening mode never calls window.open, so it keeps opening an in-app browser tab.
  • webview-links moves to 0.1.2. The upstream pin is unchanged at @deepseek-ai/dsh@0.2.1-rc.2; the fix covers both 0.2.0 and 0.2.1, which share the same click path.
  • Everything else is unchanged from v0.1.16: open-editor, diff-review (git working-tree review: staged/unstaged, accept/revert, commit/push/PR, AI review), account-login, webview-compat (the Iterator shim for older WebKit), trusted-LAN phone remote and desktop notifications.

Verification

The injected script is covered by behaviour tests (top-level page left inert, embedded window.open forwarded, non-http schemes left native, unclaimed _blank clicks forwarded, claimed clicks untouched, mailto: ignored); go vet and go test ./... are clean; and live runs of 0.2.0-rc.2 and 0.2.1-rc.2 both serve the script in <head> with the preinstalled plugin set.

Known limitations

  • The first launch downloads the 0.2.1 dependency set, which is larger than earlier lines; on a slow connection the 3-minute readiness window can expire, so let the download finish and relaunch.
  • diff-review reviews the git working tree, not in-conversation session changes; use the upstream changed-files card for those.
  • Phone access is for a trusted LAN, not a public internet relay. The host uses HTTPS and device pairing; do not expose it directly to the internet.
  • Node.js and npm must be installed separately.
  • Windows executables are not code-signed; macOS packages are signed with a Developer ID certificate and notarized.
  • Upstream DeepSeek Harness remains in developer preview and may introduce compatibility-breaking changes.
